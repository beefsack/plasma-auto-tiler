# AutoHotkey learnings for Phase 2 (Engine-driven tiling)

- Clone: upstream AutoHotkey repository at revision `d8f819c16c08a61a605a746b3e6cc18fadee6c03` (2026-09-12). Techniques studied only; no code copied (GPL).
- Scope: what AHK source/comments genuinely show about moving, filtering, focusing, hooking, and monitor/DPI handling. Gaps describe searched-path results, not universal claims.

## Highest-value learnings

- Move path is thin: `WinMove` = `GetWindowRect` + `MoveWindow(..., TRUE repaint)`, no restore, no readback, no hung guard (`source/lib/win.cpp:296-311`). Min/Max/Restore branch on `IsWindowHung`; Show/Hide do not (`source/lib/win.cpp:111-129`). Phase 2 implication: classify normal/minimized/maximized before geometry; propose preserving native minimized/maximized state in the first preview, never automatically unminimizing. Later preserve existing tiled allocations across these modes as the plan requires. Add readback/convergence and hung-window handling.
- Only `SWP_NOACTIVATE` transfers from AHK's geometry-adjacent calls: topmost toggle (`source/lib/win.cpp:1544-1550`) and top/bottom reorder (`source/lib/win.cpp:1582-1590`) are z-order-only and pass `SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE`, with a comment that the move "often fails" without `SWP_NOACTIVATE`. Those `NOMOVE`/`NOSIZE` flags disable geometry and do not apply to tiling. Phase 2 implication: adopt `SWP_NOACTIVATE` from this evidence; pair it with `SWP_NOZORDER` for tile geometry per the plan, not with `NOMOVE`/`NOSIZE`.
- Show is deliberately synchronous: comments reject `ShowWindowAsync` because later lines depend on completion, containing hung risk with `IsWindowHung` + `SW_FORCEMINIMIZE`-only-for-minimize (`source/lib/win.cpp:102-150`). Phase 2 implication: keep setter-then-readback ordering; never fire-and-forget a state change before measuring.
- Cloaked check plus a GroupDeactivate-specific classification precedent: `IsWindowCloaked` = `DwmGetWindowAttribute(DWMWA_CLOAKED=14)`, `SUCCEEDED && cloaked`, "invalid parameter" on Win7 (`source/window.cpp:1253-1259`); `DetectWindow = DetectHiddenWindows || (Visible && !Cloaked)` (`source/window.cpp:1263-1266`, repeated in match path `source/window.cpp:1643-1656`). `EnumParentFindAnyExcept`, which serves GroupDeactivate only, additionally skips hidden, disabled-without-popup, always-on-top, `WS_EX_NOACTIVATE`, bare `WS_EX_TOOLWINDOW`, `GW_OWNER`-owned, cloaked, and shell windows (`source/WinGroup.cpp:342-389`). Phase 2 implication: propose this as a conservative initial classification, with topmost/owned kept as refinable special cases rather than permanent exclusions. Study-only technique, not a product decision.
- Foreground is verify-don't-trust: AHK comments report false failures from `SetForegroundWindow`, so it sleeps and re-reads `GetForegroundWindow`, accepting a foreground window owned by the requested target (`source/window.cpp:48-85`); the full ladder adds `AttachThreadInput`, one Alt-up, then two Alt-downs, detaching afterward (`source/window.cpp:89-283`). Restoring minimized targets before activation (`source/window.cpp:118-127`) and Alt-key steps are AHK scripting behavior, not tiler policy. Phase 2 implication: independently verify focus; defer `AttachThreadInput` escalation and avoid Alt-key fallbacks. The comments also report attached-thread activation hanging on a hung modal target (`source/window.cpp:62-69`).
- AHK's general routing is `RegisterHotKey`-first with hook fallback ("override any other script or program", `source/hotkey.cpp:479-484`); hook is mandatory for `#HotIf`-without-global-variant, prefix-used-as-suffix, key-up/down pairs, and wildcard eclipse (`source/hotkey.cpp:244-251,338-358,418-449`); Win-modified mouse hotkeys force both hooks or Start menu leaks (`source/hotkey.cpp:457-477`). Phase 2 implication: our selected Win+Arrow mechanism stays direct LL hook; registration-first applies only to other future non-Win chords.
- Win-release Start-menu suppression is a mask-at-release trick: when Win/Alt is down and a suppressed hotkey fires, AHK sets `sDisguiseNextMenu` and on release sends a Ctrl down+up (`g_MenuMaskKeyVK = VK_CONTROL`, `source/globaldata.cpp:66-67`) before `CallNextHookEx` so the OS sees Win as modified (`source/hook.cpp:1420-1471`; release handling `source/hook.cpp:2011-2068`; sender `source/keyboard_mouse.cpp:1795-1799`). Ctrl/Shift already disguise; isolated Ctrl/Shift-up and Alt edge cases are documented inline. Phase 2 implication: retain our accepted vkE8 mask at Win-up while Win is held, not AHK's default Ctrl key.
- LL hook discipline is explicit: `WH_KEYBOARD_LL`/`WH_MOUSE_LL` installed on a dedicated hook thread with a message loop (`source/hook.cpp:4100-4147`); comments report slow hook returns timing out and keys passing through, so the hotstring path posts instead of blocking (`source/hook.cpp:2547-2553`). A comment flags UIPI as a possible cause of missed Alt-Tab state (`source/hook.cpp:47-53`), not a tested geometry restriction. `ChangeWindowMessageFilter` permits lower-IL `WM_CLOSE` for single-instance coordination, with a warning against general unblocking (`source/hook.h:48-68`). Phase 2 implication: keep Engine/geometry off the hook callback, address hook-loss observability, and preserve the unmanaged-elevated policy rather than widening filters.
- Per-monitor work bounds are available without `SPI_GETWORKAREA`: `MonitorGet`/`MonitorGetWorkArea` enumerate with `EnumDisplayMonitors`, read `MONITORINFOEX` via `GetMonitorInfo`, and select `rcWork` vs `rcMonitor` (`source/lib/env.cpp:92-191`, selection at `source/lib/env.cpp:163-179`); the tooltip path additionally clamps per-point via `MonitorFromPoint(..., MONITOR_DEFAULTTONEAREST)` + `GetMonitorInfo`, using `rcWork` on Win8+ to avoid taskbar overlap (`source/script2.cpp:1156-1163`). DPI posture is manifest-first: `PerMonitorV2` + `disableWindowFiltering(true)` for UWP enumeration (`source/resources/AutoHotkey.exe.manifest:50-58`); `GetDpiForWindow(Shell_TrayWnd)` with a comment that system DPI is frozen at login (`source/util.cpp:2051-2065`); per-control awareness check skips non-PM-aware controls during rescale (`source/script_gui.cpp:11192-11225`). Phase 2 implication: take per-monitor `rcWork` bounds from the start and declare PMv2; no frame-conversion formula found. (`SPI_GETWORKAREA` primary-only use remains at `source/script.cpp:638-644`.)
- UWP frame signal plus owned/hung handling: the hook detects UWP frames by `GetClassName` == `ApplicationFrameWindow` for UWP-specific dead-key translation (`source/hook.cpp:2211-2230`); first-non-child-parent walk uses `WS_CHILD` + `GetParent`, explicitly *not* the owner (`source/window.cpp:1141-1163`); hung probe prefers `IsHungAppWindow`, falls back to `SendMessageTimeout(..., SMTO_ABORTIFHUNG, 5000)` (`source/window.cpp:1197-1248`). Phase 2 implication: class-name check is one available UWP classification signal; classify owned dialogs before tiling; probe hung windows off the hot path.

## Sequencing recommendations (change Phase 2 order)

- Classify normal/minimized/maximized first; preserve native state in the first preview (proposal).
- Readback/convergence before any batching: the thin `MoveWindow` path leaves acceptance unhandled.
- Initial classification from the GroupDeactivate evidence; refine topmost/owned cases rather than excluding them permanently.
- Preserve direct LL hook and the accepted vkE8 menu-mask at release.
- Per-monitor `rcWork` bounds from the start, not primary-only work area.
- Defer `AttachThreadInput` as an optional escalation, not initial dogfood.

## Gaps (searched-path results only)

- Targeted searches of `source/` returned no `SetWinEventHook`, `EVENT_*`, or shell-hook matches; no dropped-event/coalescing guidance found there.
- No `DWMWA_EXTENDED_FRAME_BOUNDS` matches in `source/`; no `LogicalToPhysical`/frame-conversion formula found.
- `DeferWindowPos`: only a comment that it fails with mixed parents (`source/script_gui.cpp:11204-11205`).
- No `ApplicationFrameHost` handling found in searched paths (only the `ApplicationFrameWindow` class check above).
- No elevated-geometry, sleep/display-change, or Explorer-restart recovery policy found beyond the hook-miss note and filter warning.
