## Discriminating exclusions and evidence

- `kwin/src/plan-adapter-entry.ts:1610-1647` quarantines a foreground domain for one malformed eligible member. Dropping that member would turn an incomplete observation into a false departure/remove-and-readmit (`docs/decisions.md:25-29,520-527`). Hidden observation already omits just an affected domain; this is a **justified** broad-looking fence, not a safe per-window-drop fix. A bounded normal-level quarantine-cause log would improve observability, but is not ranked as fail-closed behavior.
- `kwin/src/plan-adapter.ts:1441-1485,961-1073,1960-1995` strictly validates observed membership, complete planned geometry and ambiguous adjacent output. Filtering a bad observed member or planned geometry entry could silently misplace or remove another member; treating an unreadable adjacent target as confirmed absent could unexpectedly perform a local instead of requested cross-output move. These are per-observation/request fences, not permanent disablement. The separate `workspace-send-adapter-entry.ts` route is dev-only, not a production source of findings.
- `crates/tiler-core/src/engine.rs:295-323,1607-1682,1818-1837` and `crates/tiler-protocol/src/planner_protocol.rs:1921-1924` reject invalid or post-convergence-inconsistent **individual** operations without poisoning future complete observations. Effect FFI malformed frames remain per-call; group/drag endpoint retries in the current native effect are the already-covered R/S fixes.
- Source reads of these paths and fresh, sequential bounded source-area audits are the evidence. No tests or live host behavior were used as evidence. All implementation sizes are rough production-line estimates, not commitments.
