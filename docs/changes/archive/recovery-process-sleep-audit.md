# Process-loss and sleep recovery audit (offline, archived 2026-09-28)

## Goal and boundary

- Trace Planner, tray, KWin script, native effect, compositor restart, and sleep/resume with output changes from current production source. Distinguish confirmed loss from ambiguous transport, retained state from rebuilt state, and automatic from manual recovery.
- Apply `docs/principles.md:34-48` and existing decisions. Fix only small ordinary root causes offline; larger or user-visible alternatives require a decision. No live KWin/Plasma actions by agents; user performs the plan below later.
- Evidence: current file:line citations, focused offline regressions for any fixes, required checks for touched code, `git diff --check`. Live outcome remains unverified.

## Units and acceptance

1. Audit Planner transport and loss, including service activation and layout state.
2. Audit tray process, owner/watcher transitions, publication and restart.
3. Audit KWin script and compositor reload/restart, including subscriptions and foreground lifecycle.
4. Audit native effect unload/reload and endpoint behavior.
5. Audit sleep/resume plus topology hotplug/reordering against the above paths; reconcile findings and root-cause fixes.
6. Record per-component findings, decision options and user-executable live steps with exact diagnostics and pass/fail evidence; update backlog and archive after offline checks.

## Findings and accepted evidence

- Planner (source audit): packaged `Restart=no` and on-demand D-Bus activation (`home-manager-module.nix:47-62`, `kwin/src/plan-adapter.ts:5667-5904`); old process drops in-memory topology (`crates/omnitiler/src/planner_service.rs:133-180`); confirmed absent/changed owner resets KWin's session and triggers one fresh observation without replay (`kwin/src/plan-adapter.ts:6085-6134`). Ambiguous failure probes once, retains topology unless owner absence/change is proven (`:5944-6015`); no event means no fresh activation. Dev's killed worktree process is not bus-activated (`justfile:296-324`). Logs `omnitiler:plan:recovery reason=absent|changed outcome=confirmed-loss`, `outcome=no-fresh-observation` (`plan-adapter.ts:6114,6132`). Live timing unverified.
- Tray (source audit): crashed process loses snapshot/watch registration; login XDG autostart has no crash restart (`home-manager-module.nix:34-44`, `docs/decisions.md:986-993`). Watcher absence/loss keeps process alive; name signal and existing 1s watchdog retry confirmed registration (`crates/omnitiler/src/tray_endpoint.rs:1045-1080,1331-1384`). KWin owner change revokes snapshot and fresh authenticated publications restore it (`:77-89,191-226,833-874`). Tiling is independent (`docs/decisions.md:967-978`). Logs `omnitiler:route-diag component=tray-endpoint stage=watcher|owner|projection ...` (`tray_endpoint.rs:448-599,1249-1283`). Accepted no-auto-crash-restart policy and inaccurate enabled status are user-visible decisions, not ordinary recovery fixes.
- Script and KWin: a script reload rebuilds JS observation/shortcut/drag state (`kwin/src/entry.ts:49-56`, `kwin/src/plan-adapter-entry.ts:3071-3123`); surviving Planner retains Rust domains because production uses fixed `owner=kwin-plan-adapter,generation=plan-1` (`entry.ts:55`, `crates/tiler-protocol/src/planner_protocol.rs:2017-2034`). KWin restart also recreates the native effect; packaged plugin enabled configuration governs reloading (`nixos-module.nix:22-25`). No JS tiling occurs while the script is absent. A refused initial attach now retries on `windowAdded`/`screensChanged`/`configChanged` (`plan-adapter-entry.ts:5535-5703`); hard-missing transport/timer/attach edges are terminal. No automatic script restart after intentional unload. Production does not call its optional stop handle (`entry.ts:55-56`); exact unload behavior and native stale outline require live evidence.
- Effect: native unload unregisters owned services and destroys its rendered state (`kwin/native-effect/activewindowborder.cpp:302-317`). Constructor re-seeds windows/maximize and registers independent ActiveBorder and DragOracle endpoints (`:198-255,383-435,702-748`); failed registration retries on activation/reconfigure, without a new timer (`:259-261,319-326`). Script group/preview setter submission cannot attest acceptance (`kwin/src/active-group-highlight.ts:861-873`); drag oracle pull failure settles only that drag (`kwin/src/drag-oracle-pull.ts:252-259`). Tiling still uses Plan when effect unavailable. Native logs `omnitiler:active-border:endpoint available=0|1`, `omnitiler:drag-oracle:endpoint available=0|1` (`activewindowborder.cpp:631-647`); group may wait for a new refresh edge on effect return. Note: native border visibility is computed independently of D-Bus availability (`:766-794`), although its diagnostic reason prioritizes endpoint absence (`:168-194`).
- Sleep/output: no sleep hook (source search; see `docs/changes/reliability-condition-investigation.md:125-145`); only subscribed window/scope events or next command drive reconciliation (`kwin/src/plan-adapter-entry.ts:2970-3050,3692-3706`, `kwin/src/plan-adapter.ts:4649-4711`). Planner surviving sleep retains domains (`crates/omnitiler/src/planner_service.rs:133-180`); confirmed loss fits current windows once, interrupted commands never replay (`plan-adapter.ts:6085-6134`). Output identities are tuple-bound stable keys (`kwin/src/workspace-native.ts:201-217,347-400`); removal displaces workspaces to a survivor, exact origin return reverses it (`:1184-1360`); no-survivor and unreadable topology defer without pruning (`:1144-1149,1257-1291`). Resume without a native signal remains idle until the next event or command. Logs `omnitiler:workspace:workspace-displaced:*`, `workspace-returned:*`, `workspace-displaced-deferred:*` (`workspace-native.ts:1205-1352`).

## Material follow-up

- Ordinary scoped fix completed: the already-available `screensChanged` native edge retries refused attach after a recoverable `windowList()` refusal; no timer, cap, or listener after success (`kwin/src/plan-adapter-entry.ts:5677-5694`, `kwin/tests/plan-adapter.test.ts:4697-4737`).
- Product decision: tray crashes remain absent until manual relaunch/next login (`docs/decisions.md:991-993`). Option 1 keep explicit no-auto-restart; option 2 supervise crash recovery with owner/auth guards and no arbitrary retry cap. Recommend option 2 for status resilience, with a design for reporting a persistent crash rather than silently wedging. Do not implement without authorization.
- Architectural question: KWin restart against surviving Planner retains fixed binding rather than explicitly starting a fresh generation (`kwin/src/entry.ts:55`, `crates/tiler-protocol/src/planner_protocol.rs:2017-2034`). Option 1 keep retained topology and reconcile with fresh complete windows (preserves layout; stale session risk); option 2 issue new script-instance generation (fresh near-fit; grouping can change). Recommend preserve surviving layout unless live evidence of incorrect topology; require user decision before changing generation semantics.
- Separate user-visible status issue: production tray publisher is hardcoded `isEnabled: () => false` and never calls `notifyEnabledChanged` (`kwin/src/entry.ts:13-15,49-56`, `kwin/src/tray-publisher.ts:63-71`), so an authenticated healthy snapshot can be `Passive`. Option 1 keep status as a coarse presence signal, with explicit labeling; option 2 wire status to verified adapter readiness/stop/recovery (recommended for an accurate active indicator). This changes user-visible semantics and requires a lifecycle contract; do not infer that `Passive` means tiling failed in the recovery tests.

## Accepted fix and offline verification

- `kwin/src/plan-adapter-entry.ts:5541-5544,5677-5694` now listens for `screensChanged` on the existing failed-start observer, detaching that wait on success/stop; the hard-missing transport/timer fence is untouched. `kwin/tests/plan-adapter.test.ts:4697-4737` proves a transient lister refusal followed only by a screen event, one recovery/shortcut registration, and stopped wait detachment. This cannot guarantee an event on every resume; it closes the screen-only case.
- After this change: KWin `npm test` 789/789, `npm run typecheck`; Rust `cargo test --workspace`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`; `git diff --check` pass. No native or shell source touched, no live test run.
- No new product decision is authorized for promotion to `docs/decisions.md`; existing Planner/tray/effect recovery choices are cited above. Live acceptance and the three user-visible policy questions above remain open.

## Live test plan

User-run only. Read `docs/live-kwin-testing.md` immediately before testing. Work with verified project-only resources and normal Wayland resizable clients, not existing unrelated windows. A KWin session boundary, physical input, and suspend are user actions; agents must not run these tests. If ownership, parser, baseline or restoration differs from expectation, stop that case, retain the trace and do not perform a guessed cleanup. Do not infer success from a D-Bus send or visual impression alone (`docs/live-kwin-testing.md:72-83,115-124`).

### Common capture and oracle

1. Choose **packaged session** for Planner and tray crash cases (it tests packaged D-Bus activation/XDG autostart); use `just dev trace` only for worktree script/effect scenarios after `just dev-status` says DOWN. Do not treat a worktree Planner killed under `just dev` as bus-activatable. Record startup mode, exact KWin `org.kde.KWin` owner/PID/start, exact `com.omnitiler.Planner` and `com.omnitiler.Tray` owners/PIDs/exe, `/Scripting isScriptLoaded("omnitiler-kwin")`, `/Effects` plugin loaded state, effect endpoint introspection, current desktop/output identities, each test window's frame/output/desktop and active window. Capture a `journalctl --user` cursor and KWin PID before each case; filter new KWin lines by that PID and `omnitiler:` plus a separate `QT_CATEGORY=kwin_scripting` error check. After KWin replacement use the NEW PID; preserve both records. Capture packaged tray with `journalctl --user -g "omnitiler:route-diag component=tray-endpoint"` or the `just dev trace` labeled tray stream (`docs/live-kwin-testing.md:72-81`, `docs/decisions.md:986-997`). Save the raw bus replies that establish ownership. Cursor `-- cursor: ` is a display prefix, not part of the cursor.
2. Baseline with three tiled windows in a known workspace; record stable window membership/geometry, focus, output order, and one successful `omnitiler:plan:cmd=... stage=terminal ...` line from a reversible action. Verify `omnitiler:plan:ready` (`kwin/src/plan-adapter-entry.ts:3118`). Observe geometry and membership before AND after each case, not only log count. After each controlled loss, cause one new window/scope event or existing directional shortcut if idle; differentiate event-driven recovery from requiring the user to restart a component. A silent idle interval is not evidence that loss was detected.
3. For the group endpoint, use the already documented typed, no-input read-only `GetGroupHighlightStatus`: first introspect `com.omnitiler.ActiveBorder /com/omnitiler/ActiveBorder`, then `busctl --user call com.omnitiler.ActiveBorder /com/omnitiler/ActiveBorder com.omnitiler.ActiveBorder1 GetGroupHighlightStatus` (`docs/changes/archive/active-group-highlight-design.md:50-81`). Compare `ep`, `rx`, `ok`, `has`, `vis` before/after, and observe pixels while holding Meta; `setter-submitted` or `vis=1` alone does not prove rendered output. No mutating D-Bus calls for tests.
