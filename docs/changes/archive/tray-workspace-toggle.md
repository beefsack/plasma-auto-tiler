# Tray Workspace Toggle

## Goal and accepted decisions

- User (2026-09-29): tray icon opens menu, not Settings directly; current workspace tiling checkbox, new-workspace Tiled/Floating default (Tiled initially), Settings opens the existing unified page. Only the default persists. KWin registers a keyless shortcut action and the tray invokes it over KGlobalAccel if KDE source verifies both operations; otherwise use the existing snapshot reply. No extra controls, gates or fallbacks without value.
- Orchestrator defaults confirmed by the user: KWin script owns per-workspace session state, script reload resets overrides, shared workspace mode toggles all outputs, floating stops management without moving windows, retiling releases Planner domain then uses existing fresh fit, native-only cross-boundary sends, keep active border and clear group underlay.
- KDE source verification: KWin v6.7.5 `src/scripting/scripting.cpp:376-388` registers an action with an empty key sequence; kglobalacceld v6.7.5 `src/component.cpp:206-211` invokes it by name. The D-Bus reply is void even for a missing action. A saved shortcut record may autoload a physical key; actual panel presentation and runtime delivery are not yet tested.

## Implementation and scope

- Tray `crates/plasma-auto-tiler/src/tray.rs` retains the existing meaningful disabled status row, adds a DBusMenu checkbox, default heading/radio choices and Settings, advertises `ItemIsMenu=true`, and no longer opens Settings on `Activate`. It invokes `plasma-auto-tiler-toggle-workspace-tiling` through KGlobalAccel and reports only send initiation; menu checks update from fresh KWin snapshots. Menu-only changes emit `LayoutUpdated` without redundant SNI status signals. A missing current scope disables only the workspace checkbox.
- `kwin/src/tray-publisher.ts` and `crates/plasma-auto-tiler/src/tray_endpoint.rs` use schema 2: `PublishSnapshot(i,s,i,b,s,b,b)` adds the current opaque backing-desktop scope, current tiled state and default. Revision changes on scope/state/default changes; the scope is never logged. The existing KWin-owner and generation/revision/freshness rules remain.
- `kwin/src/workspace-native.ts` initializes every existing backing desktop from `[Script-plasma-auto-tiler-kwin] defaultTiled=true`; newly discovered IDs use the then-current default, existing IDs keep their state. The tray writes only that key via `kwriteconfig6` and sends KWin's no-reply `reconfigure`, distinguishing persisted, sent and applied. The Nix tray package bakes the KF6 writer path; `devenv.nix` is untouched.
- KWin skips foreground/hidden tiling, pointer/drag/group management and native tile writes for floating domains. An explicit `DescribePlan {"op":"release-domain"}` removes the exact Planner domain with no geometry; retile remains floating until release confirms, then a fresh complete reconcile runs the existing recursive-cut/centre-split fit. Shared desktop release covers each output. Related in-flight Plan/send replies cannot write to a newly floating domain. Release failure retries on subsequent normal topology events, including when its original domain becomes hidden; no synthetic empty observation, polling loop or persistent workspace overrides.
- Project sends crossing a floating boundary use a native desktop membership write, then normal tiled-side observation/reflow. Positively sticky or multi-home movers are left unchanged rather than stripped to a single desktop. Fullscreen/maximize remain native, the independent border stays, and the group underlay is invalidated for floating focus.
