# AR3: Typed Engine behind DescribePlan

## Goal and non-goals

Introduce a typed, portable world-level Engine and a thin typed serde codec while preserving every existing DescribePlan wire shape, rejection fence, pending send/R4 transaction, diagnostic, and KWin route. Keep admit/remove observation diffing, layout policy and transaction semantics unchanged. No live KWin or host mutation. No KWin TypeScript changes.

## Approach

- Inventory command and reply shapes, validation ordering, retained state transitions, paired-session behavior and golden test coverage before editing.
- Implement coherent, separately green slices: typed codec; portable engine state/orchestration; world-level state if behavior-neutral. Preserve the legacy `Value` envelope until after the complete existing validation and pending/binding boundaries: parsing an internally tagged enum at ingress would change missing-op rejection and owner/pending side effects. Stop and report if a safe world-model replacement demands an unselected product or transaction decision.
- Document the Planner single-flight `busy` coupling without adding queueing.

## Material finding

A single permanent `Session` cannot replace the per-domain sessions without changing independent revisions/fingerprints, divergence isolation, pending scope, node identity and outer-gap handling. Decision: core Engine owns the existing per-domain sessions and pending/pair state without merging them. Eliminating the transient pair/split machinery is deferred to AR11, whose transaction model awaits the user decision. Porting the remaining JSON-coupled production logic into dependency-free core needs a typed request/reply boundary; preserve the original envelope and transaction fences until that boundary is ready.

## Accepted partial outcome (staged handover and current green slice)

- `planner_protocol.rs` decodes the `reconcile` and `update-gaps` synchronous commands once through a strict internally tagged serde enum after existing validation, pending, send and owner-binding boundaries. The production handlers no longer re-parse these two commands; the direct-evaluator reconcile test retains its test-only malformed-op wrapper. Public `Planner::evaluate` and serialized reply types remain unchanged. Roughly 30 net Rust lines added; no code moved into core yet.
- `planner_service.rs` now records the non-queuing `busy` coupling to KWin's in-flight guard. No changes to TS, D-Bus methods or logging.
- Full offline checks: `cargo fmt --check`, `cargo check --workspace --offline`, `cargo clippy --workspace --all-targets --offline` (existing style warnings), `cargo test --workspace --offline --quiet` (516 pass), `just check-portable`; KWin `npm run typecheck`, `npm test` (715 pass), `npm run build`. Existing unchanged protocol tests exercise the new production path for valid commands and strict extra-field rejection, plus the original malformed-op direct test; the independent Worker review found no changed outcome or ordering after its findings were resolved.
- Stopped before moving retained state: a single persistent Session would merge unrelated revisions and fingerprints, cause cross-domain divergence and pending interference, and collide with domain-scoped node IDs. A dependency-free Engine that **owns the existing per-domain sessions and pending pair state** can preserve these behaviors, but moving roughly 4,000 JSON-coupled lines and their validation/reply boundary as one slice is disproportionate without first converting the remaining commands and transaction payloads.
- All 19 synchronous/send/R4 commands now decode through strict internally tagged serde behind their original envelope, pending, binding and handler-local probe boundaries. Byte-exact wire goldens cover valid operations, malformed commands, workspace and directional R4 planned/ack/verify/status/cancel, and nested verify-echo error precedence. The deferred verify echo is decoded into portable lifecycle/directional types only at the original verified gate; extra operation fields remain lenient as before. The first attempted `RawValue` approach failed because internally tagged `from_value` cannot deserialize it; opaque `RawEcho` succeeds without moving the verification boundary.
- `tiler-core::seed` now implements portable near-strip fitting and focus-last seed ordering over a serde-free observed window. `tiler-core::Engine` owns the per-domain Session map, outer gaps, owner/generation binding and committed-session storage. Planner delegates those operations, but still owns pending pair transactions and command/reply orchestration. Approximately 250 production logic lines moved out of protocol; core gained approximately 450 production lines including typed carriers and new state API. Independent Worker review found no production behavior or fence change; low-risk direct private-handler op mismatch, duplicate helper/constant drift, and serde error-text coupling remain to monitor.
- Current offline checks: `cargo fmt --check`, `cargo check --workspace --offline`, `cargo clippy --workspace --all-targets --offline` (pre-existing style warnings), `cargo test --workspace --offline --quiet` (529 pass, from 516 baseline), `just check-portable` (zero normal core dependencies); `cd kwin && npm run typecheck && npm test && npm run build` (715 tests). No live KWin or host mutation.

## Exact remaining slice

Complete the serde-free event/plan/reply boundary across all 19 operations, keeping `RequestDto.command`, `Validated.raw`, wire serialization, summary helpers and fence validation in protocol. Replace the remaining JSON reply detail/operation constructors with typed core plans while preserving exact byte order and error precedence. Then move `seed_target_bounds`, `seed_session` and workspace seeding, near-layout admission handling, hotplug relocation/reprojection, canonical pair assembly/split and the workspace/R4 pending state plus ack/verify/status/cancel orchestration into `tiler-core::Engine::handle(event) -> plan/reply`. Keep distinct per-domain Session revision/fingerprint/divergence and gap state and the transient AR11 pair machinery intact. These remaining handlers and transaction replies are still interleaved across roughly 3,000-4,000 protocol production lines; extracting them without a complete typed boundary is disproportionately risky. Advance as bounded green slices with byte-level wire golden and the full offline test gates; do not mark AR3 complete or archive this note until Engine actually owns pending state and orchestration.
