# Tray Workspace Toggle - Phase 1 Proposal

## Goal, scope, acceptance

- Clicking the tray icon opens a menu with only "Tile current workspace", "New workspace behavior" (Tiled / Floating), and Settings. Settings opens the existing unified page. Use COSMIC's item grouping, not its extra controls (`docs/reference-cosmic-tray-menu.md:35-84`).
- Each workspace has session-local tiled/floating behavior. The persisted new-workspace default is Tiled unless changed. Every existing workspace starts from that default in a new KWin session; changing the default during a session affects only subsequently discovered workspaces. Switching to floating leaves native window geometry and existing intentional per-window float flags alone; switching back releases old Planner topology and fresh-adopts current eligible windows through the recursive-cut/centre-split fit.
- Phase 1 is source-based design only. Acceptance for this phase: identify real control/state/persistence routes, enumerate affected behaviors and decisions, estimate effort, mark unverified APIs. No production edits or live host operations. In particular, do not modify the staged adoption changes or `devenv.nix`.

## Source findings

1. The Rust tray is an SNI (`crates/plasma-auto-tiler/src/tray.rs:432-527`), already exporting `/Menu` as `com.canonical.dbusmenu` (`tray.rs:548-651`). `ItemIsMenu=false`; `Activate` opens the fixed unified KCM, `ContextMenu` does nothing, and the current menu contains a disabled status row plus Settings only (`tray.rs:505-523,548-585,628-643`). The guarded launcher is `tray.rs:184-227`. Change `ItemIsMenu`, remove the status row, make menu state-driven and keep Settings action. Actual Plasma left-click menu rendering is unverified. The AR13/tray records establish same-UID trust and that the prior tray has no control route (`docs/changes/archive/architecture-review-ar13-tray.md:3-12`; `docs/changes/archive/tray-carrier.md:9-19,30-51`).
2. KWin publishes `PublishSnapshot(schema,generation,revision,enabled)` to the tray on a 1-second heartbeat; production `enabled` is hardcoded true (`kwin/src/entry.ts:13-29,49-55`; `kwin/src/tray-publisher.ts:21-77,134-175`). The tray retains only owner/freshness/that boolean (`crates/plasma-auto-tiler/src/tray_endpoint.rs:15-42,76-149`), not workspace or Planner state. `DescribePlan(s)->s` is KWin-to-Planner and same-UID authorized, not an inbound script command (`crates/plasma-auto-tiler/src/planner_service.rs:27-38,189-218`). No verified callable tray-to-script D-Bus method exists; KWin's declared script `callDBus` is outbound (`kwin/src/kwin-globals.d.ts:33-48`).
3. Recommended command path: use the already-running KWin-to-tray heartbeat as a bidirectional exchange. The tray's authenticated `PublishSnapshot` reply currently returns no data (`crates/plasma-auto-tiler/src/tray_endpoint.rs:837-881`); version its wire schema and return a pending, correlated **set tiled state** intent. KWin's `callDBus` supports a trailing asynchronous reply callback (`kwin/src/kwin-globals.d.ts:33-48`). Menu click queues one desired state bound to the accepted snapshot's current scope/generation; KWin consumes it only if that scope is still current, performs the transition and publishes its outcome/correlation on the next snapshot. Retain the intent until KWin reports a terminal outcome; idempotent set rather than toggle prevents duplicate heartbeat delivery from reversing it. No new inbound KWin D-Bus method, process or polling timer. **Unverified:** exact KWin callback argument shape for a nonempty D-Bus reply and actual Plasma left-click rendering; verify offline against the pinned scripting source and fixture. Extend the KWin-published snapshot with current scope, current tiled state and default; bump revision on state/scope changes and project check/radio marks only from accepted fresh snapshots. Keep `enabled` as overall availability, not a per-workspace float indicator. Do not optimistically flip menu state on dispatch (`tray_endpoint.rs:91-175`; `tray.rs:274-406`; `kwin/src/tray-publisher.ts:49-77`).
4. The KWin workspace adapter owns the session-local backing-desktop mapping and distinguishes owned from adopted desktops (`kwin/src/workspace-native.ts:376-415,449-485,2200-2229`). Model workspace behavior there, not as per-window `floatingIds` or Planner topology. Use live desktop IDs, not logical indices (`workspace-native.ts:156-202,567-603`). The active output is the active window's output, otherwise `activeScreen`; choose `currentDesktopForScreen(output)` (`workspace-native.ts:955-981`; `kwin/src/plan-adapter-entry.ts:1002-1073`). In `per-output-local` and `global-unique`, the selected backing desktop belongs to its mapped output; in `shared`, one backing desktop spans every output (`workspace-native.ts:569-582,870-953`; `docs/decisions.md:662-674`). A shared-workspace toggle applies to all output/domain pairs using that desktop. On startup initialize all existing mapped desktops from the saved default; on later `desktopsChanged`/mapper-created IDs initialize only previously unseen IDs, retaining existing IDs' session states across output displacement. The existing topology signal path includes desktop and screen changes (`kwin/src/workspace-native.ts:538-565`; `kwin/src/plan-adapter-entry.ts:5648-5711`).
5. Floating means the domain is **unmanaged**, not that each window is marked as an intentional float: prevent foreground/hidden automatic reconcile and all geometry-producing commands for it, including drag/resize, Meta+G, sticky-tiling transitions and workspace-send/R4 planning; don't touch window geometry, `keepAbove`, or explicit `floatingIds` (`kwin/src/plan-adapter.ts:2740-2817,2916-2975,4931-5046,5049-5140`; `kwin/src/plan-adapter-entry.ts:2858-2864,3216-3238,3555-3652`; `kwin/src/workspace-send-adapter.ts:993-1031`). Native-only fullscreen/maximize toggles can still operate (`plan-adapter.ts:2820-2914`). Native external moves into floating domains keep native placement; moves out into tiled domains are observed and freshly admitted. A project workspace-send crossing this boundary should use a native-only transfer with normal source/destination observations, never apply a two-domain Rust tiling plan; source floating also needs a native-only send path if its project shortcut remains usable. A pending tiling reply must not write into a newly floating domain: gate dispatch and pre-native-write against current domain state; sequence release/retile after any related flight settles. Reuse existing event-driven resync, not polling or synthetic empty observations (`plan-adapter.ts:4481-4518,5049-5105`). Stop group-highlight queries and invalidate/clear the effect's group underlay on floating focus/switch; the independent active-window border can remain an active hint (`kwin/src/active-group-highlight.ts:656-669,742-748`; `kwin/native-effect/activewindowborder.cpp:980-1009,1074-1087`).
6. A normal reconcile is **insufficient** to re-tile: retained survivors keep their prior tree (`crates/tiler-core/src/session/world.rs:671-917`). Add an explicit no-native-write release-domain Planner operation for the exact domain(s), then a complete fresh reconcile on re-tile; never claim that windows actually present form an empty observation. Engine fresh reconcile uses the adoption fit, including the currently staged centre-split extension, and seed fallback when the fit declines (`crates/tiler-core/src/engine.rs:648-670,1069-1107`; `crates/tiler-core/src/seed.rs:69-106,240-331`). This later implementation **will touch currently staged** `crates/tiler-core/src/engine.rs` and `crates/tiler-protocol/src/planner_protocol.rs`; report/reconcile ownership before implementation. No change to staged `seed.rs` is proposed.
7. Persist only the default as one new key under `[Script-plasma-auto-tiler-kwin]` in `kwinrc`, beside `workspaceMode` and gaps (`kwin/native-effect/unifiedsettings_module.cpp:662-681,719-747`); read with `readConfig` on startup and `options.configChanged`, applying the new value only to later desktops (`kwin/src/kwin-globals.d.ts:25-58`; `kwin/src/plan-adapter-entry.ts:5291-5367`). Tray menu writes that key through KDE KConfig-compatible tooling and requests the existing KWin `reconfigure` route; publish/read back the value from KWin before showing success. `reconfigure` dispatch alone is not an application acknowledgement (`unifiedsettings_module.cpp:758-772`). **Unverified:** exact available tray-side KConfig writer/runtime dependency; packaging/dev dependencies must be checked without changing user-owned `devenv.nix` in this phase (`flake.nix:199-212`; `devenv.nix:8-20`). No tray-owned config file or persisted workspace override.

## Material decisions (production LOC, approximate, excluding tests)

| Choice | Options and consequence | Recommendation |
| --- | --- | --- |
| State authority | KWin mapping + explicit Planner release (~160-300 LOC): one host-owned behavior map, Planner retains portable layout. Planner-owned behavior (~300-500): adds host workspace/default/scope state and query protocol to core. | KWin owns mode; Planner only drops exact released domains. |
| Tray command route | Reply on existing authenticated `PublishSnapshot` heartbeat (~140-260 LOC): carries intent and correlation without a new service, up to one heartbeat of latency. Project KGlobalAccel action (~90-170): immediate dispatch but no argument/correlation and unverified keyless registration. Planner mailbox/poll (~240-400): another protocol/queue. | Existing snapshot reply; publish the result separately from command delivery. |
| Shared workspace toggle scope | All outputs showing one shared desktop (~15-35 LOC): one logical mode across the workspace. Only active output (~40-90): same workspace displays conflicting modes and menu semantics. | All outputs in `shared`; mapped output only in the other modes. |
| Project sends across a floating boundary | Native-only movement, then observe source/target (~100-180 LOC): retains workspace shortcuts without imposing tiling. Refuse project shortcut (~25-50): external/native moves still work but shortcuts unexpectedly stop. | Native-only movement, no Rust two-domain geometry. |
| Active border on floating workspace | Keep active-window hint (~0 LOC): matches its independent native effect behavior. Hide it (~80-160): needs cross-component workspace state and native border integration. | Keep border; clear tiling-specific group underlay. |
| Persisted default authority | Existing script `kwinrc` group + KWin live reread (~100-180 LOC including menu writer): one shared setting and no new config authority. Tray-only file + sync (~140-240): duplicate authority and restart-order reconciliation. | Existing script group, Tiled on absent/invalid value. |
| Script reload in same Plasma session | Reset overrides to saved default (~0-20 LOC): session-local means this controller lifetime, and explicit script reload loses toggles. Preserve through script reload (~180-320): requires another session-memory authority and recovery handoff. | Reset on script reload; no durable per-workspace history. |

## Ordinary implementation and evidence plan

- DBusMenu checkmark for current workspace, radio rows for Tiled/Floating, a noninteractive heading and Settings; emit layout updates when accepted snapshot changes. Spec defines `toggle-type`/`toggle-state` (`https://github.com/gnustep/libs-dbuskit/blob/master/Bundles/DBusMenu/com.canonical.dbusmenu.xml`); actual Plasma check/radio appearance remains unverified. Keep only the requested menu items, no existing status row. While one scope-bound set intent awaits a KWin outcome, don't enqueue another against the same stale checkmark; workspace changes invalidate pending intent rather than applying it to a different scope. Dedupe repeat heartbeat delivery by request ID until its terminal result.
- Track known desktop IDs at startup and additions; prune deleted IDs. Scope lookup at click time, not menu-open time. Keep per-window float exceptions and sticky/fullscreen/maximized rules when fresh-adopting eligible windows (`docs/decisions.md:463-535`). On a floating transition invalidate old async writes, retire each affected Planner domain after flights settle, then suppress observations; on tiling transition clear the flag after release and force complete fresh observation. A transient Planner failure logs and retries on a later normal lifecycle edge, without a fabricated release or permanent disabled state.
- Log bounded `route-diag` records with one request correlation across tray queue, KWin command acceptance, release and re-adopt, and terminal snapshot publication; include event, mode/default, scope kind, outcome, revision and recovery; no raw desktop/window identifiers or native payloads (`docs/principles.md:50-66`; `kwin/src/tray-publisher.ts:99-147`). Distinguish write persisted, KWin reconfigure sent, KWin config reread, Planner release committed and fit applied.
- Bounded units: (1) verify nonempty `PublishSnapshot` reply callback and menu rendering offline; (2) add session behavior and release protocol after staged adoption ownership is resolved; (3) tray menu/state/config integration; (4) offline tests for all three mapping modes, background/visible lifecycle, moves, pending flights, restart/default and fresh-fit. No live tests in this phase; later live work requires `docs/live-kwin-testing.md` and separate authorization.
- Recommended total: roughly **700-1,250 production LOC**, plus targeted tests, split across Rust tray/config and Planner/protocol (~370-650) and KWin TS adapters/publisher (~330-600); no native effect changes assumed. Estimate depends on the KWin callback and KConfig writer checks. Phase 1 verification: source references and `git diff --check` on this note only; no runtime acceptance claimed.
